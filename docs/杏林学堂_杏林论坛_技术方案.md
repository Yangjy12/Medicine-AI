# 杏林学堂——杏林论坛技术方案

## 1. 文档说明

本文档用于设计“杏林学堂——中医学习系统”的杏林论坛模块，覆盖帖子发布、分类板块、标签、评论、回复、点赞、收藏、浏览统计、内容搜索、内容审核、Redis 缓冲 + 批量异步落库、`parentId + rootId` 评论模型、高并发、高可用、安全校验、日志审计、前端页面和测试方案。

杏林论坛的目标是沉淀学习者的中医学习笔记、课程讨论、经验分享和问题答疑。它与医友圈即时通讯不同：论坛强调内容可搜索、可沉淀、可审核、可运营。

## 2. 模块定位

### 2.1 服务名称

后端服务：`forum-service`

前端模块：`ForumView`、`PostDetailView`、`PostEditorView`

### 2.2 核心职责

1. 论坛板块管理。
2. 帖子发布、编辑、删除。
3. 草稿保存。
4. 帖子详情。
5. 帖子列表分页。
6. 标签和分类筛选。
7. 评论与楼中楼回复。
8. 点赞、取消点赞。
9. 收藏、取消收藏。
10. 浏览量统计。
11. 热门帖子排行。
12. 帖子全文搜索。
13. 内容审核和举报。
14. 管理员置顶、加精、锁帖、删除。
15. 积分事件发送。

### 2.3 非职责边界

- 用户身份和权限由用户服务负责。
- 实时私聊和群聊由医友圈负责。
- AI 问答由 AI 助手负责。
- 视频播放和学习记录由视频服务负责。
- 图片、附件文件内容存 OSS，论坛只保存 URL 和 objectKey。

## 5.2 帖子发布

### 5.2.1 发帖流程

```text
用户提交帖子
  |
登录校验
  |
发帖限流
  |
参数校验
  |
板块状态校验
  |
内容安全检测
  |
保存帖子
  |
保存标签关系
  |
发送搜索索引同步事件
  |
发送积分事件 POST_CREATED
  |
返回帖子详情
```

### 5.2.2 帖子状态

| 状态 | 说明 |
| --- | --- |
| DRAFT | 草稿 |
| PENDING | 待审核 |
| PUBLISHED | 已发布 |
| REJECTED | 审核拒绝 |
| DELETED | 已删除 |
| LOCKED | 已锁定，不允许评论 |

第一阶段可以采用先发后审：

- 普通用户发帖直接 `PUBLISHED`。
- 命中敏感词或风险规则进入 `PENDING`。
- 管理员可以下架或删除。

第二阶段接入完整内容审核后，可改为高风险内容先审后发。

### 5.2.3 帖子内容格式

前端编辑器建议使用 Markdown 或受控富文本。

保存字段：

- `title`：纯文本。
- `summary`：自动截取纯文本摘要。
- `content`：Markdown 或 HTML。
- `content_text`：纯文本，用于搜索。

如果使用 HTML，必须后端白名单过滤。

## 5.3 草稿

草稿适合先存在 Redis，定时或用户点击保存后落 MySQL。

Redis Key：

```text
forum:draft:{userId}:{draftId}
TTL: 30 天
```

草稿内容：

```json
{
  "draftId": "uuid",
  "boardId": 1,
  "title": "学习笔记",
  "content": "……",
  "tags": ["中医基础"],
  "updatedAt": "2025-03-21T10:20:30"
}
```

## 5.6 评论模型

### 5.6.1 设计目标

传统递归评论树查询在回复层级多时容易变慢。杏林论坛采用：

```text
parentId + rootId
```

模型：

- 一级评论：`parent_id = 0`，`root_id = id`。
- 二级及以上回复：`parent_id = 被回复评论 id`，`root_id = 所属一级评论 id`。

查询详情页时：

1. 分页查询一级评论。
2. 批量查询这些一级评论下的部分回复。
3. 前端按 rootId 组装。

这样避免无限递归查询。

### 5.6.2 评论发布流程

```text
用户提交评论
  |
登录校验
  |
帖子状态校验
  |
评论限流
  |
内容安全检测
  |
如果 parentId 为空，创建一级评论
  |
如果 parentId 不为空，查询父评论并继承 rootId
  |
保存评论
  |
更新帖子评论数
  |
发送积分事件 COMMENT_CREATED
  |
发送通知事件
```

### 5.6.3 评论排序

一级评论支持：

- 默认：热度 + 时间。
- 最新：创建时间倒序。
- 最早：创建时间正序。

回复默认按创建时间正序。

### 5.6.4 评论分页

一级评论：

```http
GET /api/forum/posts/{postId}/comments?page=1&pageSize=20
```

某一级评论下更多回复：

```http
GET /api/forum/comments/{rootCommentId}/replies?page=1&pageSize=20
```

详情页首屏每个一级评论只带前 3 条回复，超过显示“展开更多回复”。

## 5.7 点赞

### 5.7.1 点赞对象

支持：

- 帖子点赞。
- 评论点赞。

### 5.7.2 幂等设计

点赞表唯一索引：

```text
uk_user_target(user_id, target_type, target_id)
```

点赞流程：

```text
用户点击点赞
  |
登录校验
  |
目标存在校验
  |
插入 like 表
  |
如果唯一键冲突，返回已点赞
  |

```

取消点赞：

- 删除 like 表记录。
- 如果确实删除成功，计数 -1。

## 5.8 收藏

收藏只支持帖子，不支持评论。

规则：

- 用户只能收藏已发布帖子。
- 重复收藏幂等返回成功。
- 收藏列表按收藏时间倒序。

## 5.9 浏览量统计

### 5.9.1 问题

帖子详情属于高频读接口。如果每次浏览都同步更新 MySQL：

- 数据库写放大明显。
- 热门帖子会造成行锁竞争。
- 查询延迟上升。

### 5.9.2 Redis 缓冲方案

浏览帖子时写 Redis：

```text
HINCRBY forum:post:view:buffer {postId} 1
ZINCRBY forum:post:hot {score} {postId}
```

同时做用户/IP 去重：

```text
forum:post:view:dedup:{postId}:{identity}
TTL: 30 分钟
```

identity：

- 登录用户使用 userId。
- 游客使用 IP + UA hash。

30 分钟内同一用户访问同一帖子只计一次有效浏览。

### 5.9.3 批量异步落库

定时任务每 10 秒或 30 秒执行：

```text
读取 forum:post:view:buffer
  |
批量聚合 postId -> increment
  |
执行批量 UPDATE post.view_count = view_count + increment
  |
成功后删除对应 Redis hash field
```

为了避免落库过程中丢失增量：

推荐用 Lua 脚本原子搬运：

```text
forum:post:view:buffer -> forum:post:view:flushing:{batchId}
```

MySQL 更新成功后删除 flushing key。

如果更新失败，下次将 flushing 数据合并回 buffer 或继续重试。

## 5.10 热度排行

Redis ZSet：

```text
forum:post:hot:day:{yyyyMMdd}
forum:post:hot:week:{yyyyww}
forum:post:hot:total
```

热度分：

```text
score = view * 1 + comment * 5 + like * 3 + favorite * 4
```

排行榜接口优先读 Redis ZSet，再批量查 MySQL 帖子摘要。

## 5.11 搜索

使用 Elasticsearch 建立帖子索引。

检索字段：

- title
- summary
- contentText
- tags
- authorNickname
- boardName

支持：

- 关键词搜索。
- 高亮标题。
- 板块过滤。
- 标签过滤。
- 发布时间排序。
- 热度排序。

同步策略：

- 发帖后发送 `POST_INDEX_UPSERT`。
- 编辑后发送 `POST_INDEX_UPSERT`。
- 删除后发送 `POST_INDEX_DELETE`。
- 审核状态变化后同步索引。

ES 异常时不影响发帖主流程，写 outbox 或 MQ 重试。

## 5.12 举报和审核

### 5.12.1 举报对象

- 帖子。
- 评论。

举报原因：

- 广告。
- 违规医疗建议。
- 攻击辱骂。
- 色情低俗。
- 侵权。
- 其他。

### 5.12.2 审核动作

管理员可以：

- 通过。
- 驳回。
- 删除。
- 锁帖。
- 置顶。
- 加精。
- 撤销置顶。
- 撤销加精。

所有管理动作必须写审计日志。

## 6. 数据库设计

## 6.1 forum_board 板块表

```sql
CREATE TABLE forum_board (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(64) NOT NULL,
  description VARCHAR(255) DEFAULT NULL,
  icon VARCHAR(128) DEFAULT NULL,
  sort_order INT NOT NULL DEFAULT 0,
  status VARCHAR(32) NOT NULL DEFAULT 'ENABLED',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_name (name),
  KEY idx_status_sort (status, sort_order)
) COMMENT='论坛板块表';
```

## 6.2 forum_post 帖子表

```sql
CREATE TABLE forum_post (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  board_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  title VARCHAR(128) NOT NULL,
  summary VARCHAR(512) DEFAULT NULL,
  content MEDIUMTEXT NOT NULL,
  content_text MEDIUMTEXT DEFAULT NULL,
  cover_url VARCHAR(512) DEFAULT NULL,
  cover_object_key VARCHAR(512) DEFAULT NULL,
  view_count BIGINT NOT NULL DEFAULT 0,
  like_count BIGINT NOT NULL DEFAULT 0,
  comment_count BIGINT NOT NULL DEFAULT 0,
  favorite_count BIGINT NOT NULL DEFAULT 0,
  hot_score BIGINT NOT NULL DEFAULT 0,
  top_flag TINYINT NOT NULL DEFAULT 0,
  essence_flag TINYINT NOT NULL DEFAULT 0,
  status VARCHAR(32) NOT NULL DEFAULT 'PUBLISHED',
  publish_time DATETIME DEFAULT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_board_status_time (board_id, status, publish_time),
  KEY idx_user_time (user_id, created_at),
  KEY idx_hot (status, hot_score),
  KEY idx_publish_time (status, publish_time)
) COMMENT='论坛帖子表';
```

## 6.3 forum_post_tag 标签关系表

```sql
CREATE TABLE forum_post_tag (

  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_post_tag (post_id, tag_name),
  KEY idx_tag (tag_name)

```

## 6.4 forum_comment 评论表

```sql
CREATE TABLE forum_comment (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  post_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  parent_id BIGINT NOT NULL DEFAULT 0,
  root_id BIGINT NOT NULL DEFAULT 0,
  reply_to_user_id BIGINT DEFAULT NULL,
  content VARCHAR(2000) NOT NULL,
  like_count BIGINT NOT NULL DEFAULT 0,
  status VARCHAR(32) NOT NULL DEFAULT 'NORMAL',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_post_root_time (post_id, root_id, created_at),
  KEY idx_post_parent_time (post_id, parent_id, created_at),
  KEY idx_user_time (user_id, created_at)
) COMMENT='论坛评论表';
```

说明：

- 一级评论创建后需要将 `root_id` 更新为自身 `id`。
- 回复评论直接继承父评论的 `root_id`。


## 12. 高并发设计

## 12.1 帖子详情高并发

详情页读多写少。

措施：

- 帖子详情缓存 Redis。
- 浏览数 Redis 缓冲。
- 用户点赞收藏状态单独查询。
- 评论分页独立加载。
- 热门帖子可 Caffeine 本地缓存。

## 12.2 浏览量高频写

使用 Redis Hash 缓冲，定时批量写 MySQL，避免每次访问都更新数据库。

一致性说明：

- 前端展示的浏览数可用 `MySQL view_count + Redis buffer increment`。
- MySQL 最终一致即可。
- 系统崩溃时 flushing key 可恢复。

## 12.3 评论高并发

措施：

- 评论表按 `post_id, root_id, created_at` 建索引。
- 一级评论和回复分开分页。
- 评论计数使用数据库原子更新。
- 热门帖子评论可短 TTL 缓存。
- 评论发布限流。

## 12.4 点赞高并发

措施：

- 点赞表唯一索引保证幂等。
- Redis 缓存用户点赞状态。
- 计数可以同步更新数据库，也可 Redis 缓冲后异步落库。
- 第一阶段同步更新更简单，热点优化时再异步化。

## 12.5 搜索高并发

措施：

- 搜索走 Elasticsearch。
- 搜索关键词限长。
- 搜索接口限流。
- 热门搜索结果短 TTL 缓存。
- ES 不可用时降级为 MySQL 标题模糊搜索或提示搜索暂不可用。

## 13. 高可用设计

## 13.1 服务无状态

论坛服务不依赖本地 Session，用户身份由 JWT 校验。缓存和状态存 Redis/MySQL，可以横向扩展。

## 13.2 依赖降级

| 依赖 | 降级策略 |
| --- | --- |
| Redis 异常 | 帖子可读写，但浏览统计、热点榜和草稿降级 |
| Elasticsearch 异常 | 搜索不可用或降级 MySQL 简单搜索 |
| RabbitMQ 异常 | 索引同步和积分事件进入 outbox 补偿 |
| OSS 异常 | 图片上传失败，文本发帖可用 |
| MySQL 异常 | 核心读写不可用 |

## 13.3 Outbox 事件补偿

对关键事件使用 outbox：

- POST_CREATED
- COMMENT_CREATED
- POST_INDEX_UPSERT
- POST_INDEX_DELETE
- POST_AUDIT_CREATED

流程：

```text
业务事务内写帖子/评论
  |
同事务写 outbox_event
  |
后台任务发送 MQ
  |
成功后标记 SENT
  |
失败重试
```

## 13.4 定时任务

定时任务：

- 浏览量批量落库。
- 热度分重算。
- 草稿过期清理。
- ES 索引失败重试。
- 举报超时提醒。

多实例时定时任务必须加分布式锁：

```text
lock:forum:view-flush
```

## 14. 安全设计

## 14.1 权限校验

规则：

- 未登录用户可浏览公开帖子。
- 登录用户可发帖、评论、点赞、收藏。
- 作者可编辑和删除自己的帖子。
- 作者可删除自己的评论。
- 管理员可管理所有帖子和评论。
- 锁定帖子不允许普通用户评论。
- 删除帖子不允许访问详情。

## 14.2 入参校验

标题：

- 5 到 128 字。
- 不允许纯特殊符号。

正文：

- 10 到 20000 字。
- 过滤危险 HTML。

评论：

- 1 到 2000 字。
- 禁止空白内容。

标签：

- 最多 5 个。
- 单个标签 2 到 20 字。
- 只允许中文、英文、数字。

## 14.3 XSS 防护

如果使用 Markdown：

- 后端保存原始 Markdown。
- 前端渲染 Markdown 时开启 HTML 禁用或白名单过滤。
- 链接添加 `rel="noopener noreferrer"`。

如果使用富文本：

- 后端通过白名单过滤标签和属性。
- 禁止 script、iframe、onerror、onclick。

## 14.4 SQL 注入防护

- JPA 参数绑定。
- 排序字段白名单。
- ES 查询也要限制字段，不拼接原始 JSON。

## 14.5 防刷策略

| 行为 | 限制 |
| --- | ---: |
| 发帖 | 10 篇/小时 |
| 评论 | 30 条/分钟 |
| 点赞 | 120 次/分钟 |
| 收藏 | 60 次/分钟 |
| 举报 | 20 次/小时 |
| 搜索 | 60 次/分钟 |

维度：

- userId。
- IP。
- deviceId。

## 14.6 内容风控

风险内容：

- 虚假医疗承诺。
- 明确处方剂量。
- 广告引流。
- 攻击辱骂。
- 违法内容。

处理：

- 命中低风险：发布后标记待复核。
- 命中高风险：进入待审核。
- 严重违规：拒绝发布并记录风控日志。

## 18. 开发优先级

第一阶段 MVP：

1. 板块表和初始化数据。
2. 帖子发布、列表、详情。
3. 评论 `parentId + rootId` 模型。
4. 点赞、收藏。
5. 浏览统计 Redis 缓冲 + 定时落库。
6. 我的帖子、我的收藏。
7. 管理员删除、锁帖、置顶、加精。
8. 基础日志和 traceId。

第二阶段增强：

1. Elasticsearch 全文搜索。
2. 举报和审核工作台。
3. 图片附件上传。
4. 草稿自动保存。
5. 热榜和推荐。
6. Outbox 事件补偿。
7. AI 总结高质量帖子。

## 19. 总结

杏林论坛的核心是“可沉淀、可检索、可治理”。设计上用 MySQL 保存核心内容，用 Redis 承接高频计数和热点数据，用 Elasticsearch 支撑搜索，用 RabbitMQ 解耦积分、索引和审计。

关键原则：

- 评论使用 `parentId + rootId`，避免递归查询。
- 浏览量 Redis 缓冲，批量异步落库，降低数据库 I/O。
- 点赞收藏依赖唯一索引保证幂等。
- 帖子内容必须做 XSS 和风控校验。
- 管理动作必须写审计日志。
- 搜索索引与主库最终一致，失败可补偿。
